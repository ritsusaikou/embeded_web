## 测量方法

| 项目 | 方法 |
| --- | --- |
| 页面体积 | `dist/` 全量大小 + 单页 gzip 后大小 |
| 内存 | `ps -o rss= -C nginx` 汇总，`top` 交叉核对 |
| TTFB | `curl -o /dev/null -s -w "%{time_starttransfer}"` 取 20 次中位数 |
| 并发 | `ab -n 2000 -c 20 http://板子/` |
| CPU | 压测期间 `top` 采样的 nginx 进程占用 |

对比机：宿主机（x86_64，4 核）跑同一份 `dist/`，与 i.MX6ULL 使用同一份 Nginx 配置（`worker_processes 1`）。

## 一、构建体积

| 指标 | 数值 |
| --- | --- |
| `dist/` 全站（14 个页面） | 约 320 KB |
| 单个 HTML（未压缩） | 11–16 KB |
| 单个 HTML（gzip 后） | 3.4–4.8 KB |
| CSS（全站共用一份） | 14 KB / gzip 3.1 KB |
| JS | 0 KB（页面内仅 1 段约 0.4KB 的状态刷新脚本） |

一个页面下载完约 **8 KB**。这意味着在 2G 网络下首屏也不到 1 秒。

## 二、Nginx 常驻内存

| 环境 | master | worker | 合计 RSS |
| --- | --- | --- | --- |
| x86_64 | 9.6 MB | 5.1 MB | 14.7 MB |
| **i.MX6ULL** | 2.1 MB | 1.1 MB | **3.2 MB** |

armhf 上的二进制更小，加上 `worker_connections 128`、`access_log off`，常驻内存只有 x86 的 1/4。512MB 里占 0.6%。

## 三、TTFB

| 链路 | 中位数 | 说明 |
| --- | --- | --- |
| 局域网直连板子 | 3.2 ms | 内核 `sendfile` 零拷贝 |
| x86 本机 | 1.1 ms | 参考值 |
| 公网经 frp 隧道 | 47 ms | 主要开销在公网 RTT 与 TCP 隧道封装 |

TTFB 的差距几乎全部来自网络往返，**不是板子慢**。这一点很重要：优化方向应该是链路，而不是代码。

## 四、并发能力

`ab -n 2000 -c 20`，请求单页 HTML：

| 环境 | 请求/秒 | 平均延迟 | 失败数 |
| --- | --- | --- | --- |
| x86_64 | 8 400 | 2.3 ms | 0 |
| i.MX6ULL | 780 | 25 ms | 0 |

单核 A7 + 百兆网口，780 req/s 已经接近网口与中断处理的上限。对课程项目这种访问量来说，余量三个数量级。

## 五、CPU 与压缩策略

压测期间单核占用约 62%（`top` 峰值），其中相当一部分花在 gzip 上。改成**构建时预压缩 + `gzip_static on`** 后：

| 策略 | 单请求 CPU | 吞吐 |
| --- | --- | --- |
| 运行时 `gzip on`（level 5） | 约 4.1 ms | 430 req/s |
| **`gzip_static on`** | 约 0.4 ms | **780 req/s** |

同一份内容，把压缩从「每次请求都算」改成「构建时算一次」，吞吐提升约 80%。这是本次优化里性价比最高的一项，成本只是构建脚本里多一行 `find ... -exec gzip -9 -k`。

## 设计目标达成情况

| 目标 | 设定值 | 实测 | 结论 |
| --- | --- | --- | --- |
| 页面体积 | < 100 KB/页 | 8 KB/页 | 达成 |
| 框架 JS | 0 KB | 0 KB | 达成 |
| Nginx 常驻内存 | < 10 MB | 3.2 MB | 达成 |
| 局域网 TTFB | < 50 ms | 3.2 ms | 达成 |
| 公网可访问 | 域名 + HTTPS | 已上线 | 达成 |

## 结论

这五组数据支撑了一个判断：**在 512MB 的开发板上跑一个网站，瓶颈从来不是 CPU 或内存，而是选错了运行时。** 换掉 Node SSR 之后，内存从「要精打细算」变成「可以忽略不计」。

同时也暴露了一个反直觉的点：**TTFB 的 47ms 里，板子只贡献了 3ms**。如果只看「公网访问有点慢」就去优化板子上的 Nginx 参数，方向完全是错的。先量，再改。
